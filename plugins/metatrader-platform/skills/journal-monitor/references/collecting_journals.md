# Collecting Journal Logs From Wine MT5 on Linux

For setups running MT5 terminals under Wine (one container/prefix per account),
you need to centralize journal files before monitoring them. The monitor scans
a directory; what matters is that all `JournalLog-*.log` files end up there.

## Default log locations

Inside each Wine prefix, MT5 writes journals to:

```
<WINEPREFIX>/drive_c/users/<user>/AppData/Roaming/MetaQuotes/Terminal/<terminal_hash>/MQL5/Logs/
```

The `<terminal_hash>` is a 32-character hex string generated by MT5. There's
usually only one per prefix, so a glob works:

```
<WINEPREFIX>/drive_c/users/*/AppData/Roaming/MetaQuotes/Terminal/*/MQL5/Logs/JournalLog-*.log
```

## Option 1 — symlink the logs dir

Simplest for a single MT5 prefix:

```bash
ln -s \
  "$WINEPREFIX/drive_c/users/marin/AppData/Roaming/MetaQuotes/Terminal/abcd1234.../MQL5/Logs" \
  ~/mt5-journals/broker-a
```

Then point `--path ~/mt5-journals/broker-a` at it.

## Option 2 — rsync nightly

Robust when you have many prefixes and want a snapshot at a fixed time. Put in
cron:

```cron
# Every night at 01:55, snapshot journals from each prefix
55 1 * * *  /home/user/bin/collect-journals.sh
```

`collect-journals.sh`:

```bash
#!/bin/bash
set -euo pipefail

DEST=/home/user/mt5-journals

declare -A PREFIXES=(
  [broker-a]=/home/user/.wine-broker-a
  [broker-b]=/home/user/.wine-broker-b
  [broker-c]=/home/user/.wine-broker-c
)

for broker in "${!PREFIXES[@]}"; do
  src="${PREFIXES[$broker]}/drive_c/users"
  dst="$DEST/$broker"
  mkdir -p "$dst"
  find "$src" -type f -name 'JournalLog-*.log' -print0 \
    | xargs -0 -I{} cp -n {} "$dst/"
done
```

The `-n` flag preserves existing files (journals are immutable once the trading
day ends).

## Option 3 — Docker/container setups

If you run MT5 in Docker containers (e.g. `dockur/windows`), mount a host
volume at the terminal logs path:

```yaml
# docker-compose snippet
services:
  mt5-instance:
    volumes:
      - /home/user/mt5-journals/broker-a:/config/mt5/MQL5/Logs
```

The exact in-container path depends on the image. For `dockur/windows` running
MT5 inside the VM, you'd typically expose the Windows directory via SMB and
mount it read-only on the Linux host, then run the monitor against the mount.

## Option 4 — Backtest Manager integration

If journals are inside Backtest Manager's container file tree, the simplest
pattern is a sidecar volume:

```yaml
services:
  backtest-manager:
    # existing config
  journal-collector:
    image: alpine
    volumes:
      - /home/user/mt5-journals:/out
      - bt_mt5_state:/mt5-state:ro
    command: >
      sh -c 'while true; do
        find /mt5-state -name "JournalLog-*.log" -exec cp -n {} /out/ \;
        sleep 3600
      done'
```

## Cron entry for the monitor itself

Once journals are syncing, schedule the analyser:

```cron
# Run at 02:00, analyse last 2 days, push alerts to Discord
0 2 * * *  cd /home/user/mt5-monitor && \
  python scripts/monitor.py --config monitor.yaml > /var/log/mt5-monitor.log 2>&1
```

`monitor.yaml` should point `paths:` at wherever your sync script drops the
logs. See `scripts/config.example.yaml` for the full config shape.

## Retention

MT5 keeps daily logs indefinitely by default. If you want to rotate:

```bash
# Keep 90 days of journals
find ~/mt5-journals -name 'JournalLog-*.log' -mtime +90 -delete
```

The monitor doesn't delete anything — it only reads.
